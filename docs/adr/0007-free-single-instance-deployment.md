# 7. Free, single-instance deployment

**Status:** accepted

## Context

The project runs on free plans: Neon (PostgreSQL), Render (the API, which sleeps after 15 idle minutes)
and Vercel (the web app). It must stay correct when the API wakes up cold, and cost nothing to leave on.

## Decision

- One API instance. Rate limits, the WebSocket hub and the scheduler live in its memory; correctness
  never depends on them (limits only forgive on restart; the outbox and sweeps catch up on wake-up).
- The browser reaches the API through the web app's `/api` rewrite (first-party cookie, no CORS); the
  WebSocket goes straight to the API with a one-time ticket.
- Migrations run when the API's Docker image starts, over Neon's direct connection; the app uses the
  pooled one with a small pool. CI checks the schema against the migrations (drift) and builds the image.
- The landing page calls `/health` on load so a sleeping API starts waking while the visitor reads, and
  says so honestly ("waking the server, ~40 s").
- Secrets are platform settings, never in the repository (`SIGNING_SECRET` is generated by Render).

## Consequences

- Scaling out would need shared state for limits and sockets (Redis or `LISTEN/NOTIFY`) and a single
  scheduler leader; the outbox's `SKIP LOCKED` claiming already tolerates several workers.
